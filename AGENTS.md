# QORVYNA AI — coding agent instructions

This is the single project-level instruction file for coding agents. It covers
**development workflow only**. It does not describe, configure, or replace
QORVYNA's runtime AI agent engine under `src/lib/ai/` and `src/lib/server/`.

## Ground rules

- Preserve the existing Next.js App Router + Firebase (Auth, Firestore)
  architecture. Firestore is canonical; API mutations run through existing
  server routes and ownership/RBAC checks.
- Never add secrets to source, tests, fixtures, or documentation. Use the
  existing environment variables and deployment secret stores.
- Keep provider/model claims honest. A model, provider, tool, or platform
  integration is "implemented" only when source exists, and "verified" only
  when an actual end-to-end check was performed in this checkout.
- Prefer the repository's existing conventions: TypeScript strict mode, Zod
  validation, shared components, `src/lib` boundaries, and Vitest tests next to
  the existing `tests/` suite.
- Validation gates for a normal change: `npm run typecheck`, `npm test`, and
  `npm run build`. Native frontend changes also use `npm run native:check`.
  Do not run full Windows/Android release builds unless a native configuration
  changed and the build is required to validate it.
- Do not hand-edit files generated by the Specify CLI (`.github/agents`,
  `.github/prompts`, `.specify/templates`, `.specify/scripts`). Upgrade them
  with `specify integration upgrade` / `specify self upgrade` instead.

## Spec-Driven Development

- Governance: `.specify/memory/constitution.md`. It is the source of truth for
  project principles; feature plans and tasks are checked against it.
- As-built baseline: `docs/specs/baseline/README.md`. Status labels there are
  explicit — do not treat planned capabilities as implemented ones.
- Official Spec Kit commands are installed as GitHub Copilot prompt/agent files
  under `.github/prompts/` and `.github/agents/`. Invoke them as
  `/speckit.constitution`, `/speckit.specify`, `/speckit.clarify`,
  `/speckit.plan`, `/speckit.checklist`, `/speckit.tasks`, `/speckit.analyze`,
  `/speckit.implement`, and `/speckit.converge`.
- The short workflow is constitution → specify → plan → tasks → implement.
  Production features add clarify, checklist, and analyze as quality gates.
- Spec Kit is a development methodology. Never route user chat, agent tasks,
  or tool calls through it; those continue to use the application's own
  orchestration.
